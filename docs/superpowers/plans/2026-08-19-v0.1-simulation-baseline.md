# V0.1 Simulation Baseline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first testable vertical slice of the reusable greenhouse mobile-manipulation simulation baseline: known scene/route data, deterministic mission-state semantics, settling-based arm release, and ROS-facing adapter contracts ready for Gazebo/Nav2/MoveIt integration.

**Architecture:** Keep mission semantics in a dependency-free C++17 core. ROS 2 packages wrap that core and translate stable mission commands/events to Nav2 and MoveIt 2. World truth and route definitions live in YAML and are validated independently so simulator assets can evolve without changing mission logic.

**Tech Stack:** C++17, CMake/CTest, ROS 2 Humble, ament_cmake, Python 3 + PyYAML for schema tests, Nav2, MoveIt 2, RViz 2, Gazebo.

**Spec:** `docs/superpowers/specs/2026-08-19-v0.1-simulation-baseline-design.md`

## Global Constraints

- V0.1 uses a known world; no perception-generated target poses.
- No LLM/VLM planning, dynamic-obstacle reasoning, automatic grasp-point estimation, or simultaneous whole-body base-arm control.
- `agt_mission_core` contains no ROS/Gazebo/Nav2/MoveIt dependency.
- Invalid mission transitions must be rejected explicitly.
- Default settling thresholds are `0.01 m/s`, `0.01 rad/s`, continuously for `0.5 s`.
- Existing MK Mini geometry is provisional and must be labeled unverified.
- Implementation follows RED -> GREEN -> REFACTOR.
